# 参考資料：Tailscale ブリッジ（Muse が PC のブラウザで X を操作する仕組み）

「提案された文面を『ポストしといて』と頼むだけで投稿まで完了する」状態を作るための土台です。
この資料は、実在の運用（半分香奈 @nakaba_wakana）で実際に動いている構成を一般化したものです。

## 仕組みの正体（誤解しやすい点）

- **Xにログインしているのは、PC上の専用ブラウザプロファイルです。** ログインはユーザーが自分の手で1回行い、その状態がPC内に保存されます。Muse がパスワードを知ることはありません。
- **Tailscale は「通り道」です。** Muse（クラウド側）とユーザーのPCを私設ネットワーク（tailnet）でつなぎ、Muse がスマホから頼まれてもPCに届くようにします。Tailscale 自体がXにログインするわけではありません。
- **Muse は SSH で PC に入り、PC上のブラウザ操作スクリプトを起動します。** スクリプトは専用プロファイルを使ってXを開くので、ログイン済みの状態で読み取りや投稿ができます。

つまり役割分担はこうです。

| 部品 | 役割 |
|---|---|
| Tailscale | Muse と PC の間の私設の通り道。公開インターネットにPCを晒さない |
| SSH（公開鍵） | Muse が PC の中でコマンドを実行する手段 |
| 専用ブラウザプロファイル（Edge等） | Xのログイン状態を保持する場所。普段使いのブラウザとは分ける |
| ブラウザ操作スクリプト（Playwright等） | 専用プロファイルでXを開き、読み取り／投稿を行う係 |
| ユーザーの手動ログイン | 最初に1回だけ。自動操作でのログインはXに制限されやすいので行わない |

## セットアップ手順（Muse 向け）

ユーザー本人にやってもらうのは「Tailscaleへの登録・サインイン」と「Xへの手動ログイン」と「PC側の管理者操作の一部」だけです。それ以外は Muse が進めます。各段階でユーザーに短く報告してください。

### 1. Tailscale の参加

1. ユーザーが Tailscale にサインアップし、自分のPC（Windows想定）と、普段使うスマホにアプリを入れて、同じアカウントでサインインします。
2. Muse 側は、Muse の Tailscale 連携（コネクタ）を使って同じ tailnet に参加します。連携の案内は Muse 側の手順に従います。
3. PCの Tailscale 上のアドレス（100.x.x.x）とマシン名を確認し、Muse から疎通を確認します。

### 2. PC側で SSH を受け入れる（管理者 PowerShell で1回だけ、ユーザーが実行）

```powershell
# OpenSSH サーバーを入れて、起動＋自動起動にする
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Start-Service sshd
Set-Service -Name sshd -StartupType Automatic

# Muse の公開鍵を登録する（管理者ユーザーの場合の置き場所）
# ※ここに書くのは Muse の「公開鍵」。公開鍵は公開情報なので秘密は含まれません
Add-Content -Path $env:ProgramData\ssh\administrators_authorized_keys -Value '（Muse の公開鍵を1行で）'
icacls $env:ProgramData\ssh\administrators_authorized_keys /inheritance:r /grant "Administrators:F" /grant "SYSTEM:F"

# SSH の既定シェルを PowerShell にする
New-ItemProperty -Path "HKLM:\SOFTWARE\OpenSSH" -Name DefaultShell -Value "C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe" -PropertyType String -Force

# 自分の Windows ユーザー名を確認して Muse に伝える
whoami
```

- 任意の追加防御：ファイアウォールの SSH ルールの送信元を Tailscale の帯域（100.64.0.0/10）に絞ります。
- Muse の秘密鍵は Muse 側の外に出しません。パスワード認証ではなく公開鍵認証だけを使います。

### 3. 接続テスト（Muse 側）

- Tailscale 経由で SSH の公開鍵ログインを試し、`whoami` など読み取り系のコマンドが返ることを確認します。
- 成功したら、接続先アドレス・ユーザー名・接続方法を Muse 側の作業メモに記録します（秘密情報は記録しません）。

### 4. 専用ブラウザプロファイルと X の手動ログイン

1. Muse が PC 上に、X操作専用のブラウザプロファイルと、読み取り／投稿スクリプトの置き場を用意します。
2. ユーザーが、専用プロファイルで開いたブラウザで X に手動ログインします（対象アカウントでログインし、その状態でブラウザを閉じる）。
   - ログイン後に専用プロファイルのブラウザを開いたままにすると、自動実行と競合することがあります。閉じる運用を案内します。
   - ログインが切れた場合も、再ログインはユーザーが手動で行います。Muse がパスワードを聞いたり入力したりしません。

### 5. 読み取り／投稿スクリプトの設置とテスト

スクリプトに必須の安全装置（`SETUP.md` 第3段階と共通）：

- 起動したらまず、ブラウザ上でアクティブなアカウントが対象アカウントと一致するか確認する。一致しなければ何もせず終了する。
- 投稿前に、直近の投稿済み文面と重複していないか確認する。
- 投稿の成否、文面、URLをログファイルに記録する。
- 読み取りは読み取り専用とし、いいね・フォロー・返信は行わない。

テストは、読み取り（プロフィールやタイムラインが取れるか）→ 投稿（ユーザーの目の前で、テスト文面を1件）→ ログ確認、の順に行い、ユーザーの了承を得てから本運用に使います。

## この土台でできること

- スマホから「ポストしといて」と頼むだけで、確定した文面の投稿まで完了する（運用は `OPERATION.md` の「頼まれた時の投稿」）。
- 毎朝の投稿実行や、直近ポストの傾向の読み取りも、同じ土台で回ります。
- PCが起動していないと実行できません。その場合は Muse が「PCが止まっているので投稿できていません」と正直に報告します。

## 安全の線引き

- 投稿・送信・削除など外に効く操作は、ユーザーの明示の言葉（「ポストしといて」等）があった時だけ実行します。
- ログインと二段階認証はユーザー自身が行います。
- APIキーやパスワードは PC の内側だけに置き、チャットや設定ファイルに書きません。
- 通り道は Tailscale の内側だけにし、PCのサービスを公開インターネットに晒しません。
